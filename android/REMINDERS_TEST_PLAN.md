# 第一版安卓强提醒与语音真机验收

当前为源码实现，未在真实手机上验证，也不能保证绕过系统限制。强提醒采用系统高优先通知、声音与振动、有限次数复提醒；不使用全屏意图、不绕过勿扰、不持续运行后台服务。

## 设备前提

- 用户已确认手机为华为 Mate 60 Pro，系统为 HarmonyOS 4.2.0.198；本次按可运行 Android APK 的 4.2 环境准备安装测试包，实际安装、语音和提醒仍需在本人手机验证。本结论不扩展到 HarmonyOS 5 / NEXT。
- 在可运行 APK 的设备上，允许通知、锁屏通知和提醒通知渠道声音/振动；可选允许“闹钟与提醒”精准时间权限。
- 华为系统若提供“应用启动管理”，检查本应用的自启动与后台活动；不要使用未经核实的厂商私有跳转。
- WHOOP 的本机 Health Connect 路线是可选项，不能假定 Mate 60 Pro 支持；不可用时返回明确提示，打卡与语音/文字记录不受影响。

## 逐项验收

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 首次提醒 | 给今天添加未完成训练，将检查时间设为几分钟后，打开提醒 | 设定时间后出现声音/振动/横幅；实际效果遵守系统渠道设置 |
| 锁屏 | 普通退出到桌面并锁屏，等待到点 | 不依赖 WebView 打开；按系统权限与省电策略显示锁屏通知 |
| 稍后提醒 | 通知中点“30分钟后提醒” | 当前通知取消，按间隔再次检查；不是直接标为完成 |
| 有限次数 | 间隔设15分钟、每类最多3次，保持未完成 | 初次加复提醒合计最多3次/类/天；到上限后不继续响 |
| 完成后停止 | 第一次提醒后将当天训练全部打卡 | 当前训练通知取消，当天后续训练复提醒停止；饮食提醒独立 |
| 明确跳过 | 将当天剩余训练逐项跳过 | 视为已处理安排，不继续追提醒；历史原因仍保留 |
| 饮食完整 | 当天食物记录后点“已记全” | 取消当前饮食提醒，后续不继续提醒；新增食物后会按未完成状态重新检查 |
| 待补全语音备注 | 当天留有foodNotes，并恢复一份foodComplete=true的旧备份 | 仍视为饮食未完成，继续按次数上限提醒，不能被过时的已记全标记停止 |
| 未打开当天 | 事先建当日星期的重复模板，跨天后不打开App | 到点直接根据模板检查，仍可提醒，不要求先用WebView生成当天记录 |
| 无训练安排 | 当天没有项目且无周计划 | 不制造无意义训练提醒；饮食检查仍独立进行 |
| 到期同时保存 | 接近到点时保存饮食或设置 | 不把已到期检查取消后误移到第二天 |
| 静默时段 | 起始检查时间在静默之外，复提醒落入22:30–07:00 | 静默时段不响；跨日复提醒结束，下一天按有效的日常检查时间重新检查，不在次晨补记前一天目标 |
| 旧备份时间冲突 | 恢复训练检查23:00、静默22:30–07:00且饮食检查20:30的备份 | 只暂停训练提醒，显示“训练检查时间位于静默时段，此提醒已暂停，请调整设置”；饮食提醒仍正常，不移到次日07:00消耗次数 |
| 静默边界 | 恢复起始检查时间等于静默开始、静默结束的配置；另测静默开始=结束 | 静默开始包含、静默结束不包含；两端相等表示不设静默；冲突只影响对应一类提醒 |
| 深夜恢复 | 起始检查18:30有效，23:00开启或恢复提醒，静默22:30–07:00 | 不把当天补提醒移成次晨07:00并消耗次日次数；下一天按18:30正常检查 |
| 拒绝通知 | 拒绝通知后等待到点 | 不报崩溃、不不断重试；页面显示权限状态；允许通知并重新打开后可重新检查 |
| 精准权限拒绝 | 不允许精准闹钟 | 降级为系统非精准提醒并显示可能延迟；没有SecurityException崩溃 |
| 重启/改时区 | 设置后重启，或改系统时间/时区 | 重新安排本地时间提醒，次数仍按当地日期限制 |
| 强行停止 | 系统设置强行停止App，再等到点 | 不承诺提醒；重新打开后恢复安排并作状态提示 |
| 勿扰/静音 | 开启勿扰或关渠道声音 | 尊重系统设置；不擅自播放绕过系统的声音 |
| 语音成功 | 饮食页点语音，说“午餐米饭150克” | 系统识别文字回填供用户确认；不会直接记成精确营养值 |
| 语音取消 | 打开系统识别后返回 | 返回cancelled，不创建食物记录 |
| 语音不可用 | 无系统识别服务或相关服务无麦克风权限 | 提示使用键盘语音或手动文字，界面继续可用 |
| 非Google语音 | 在实际Mate 60 Pro上验证RecognizerIntent的处理程序 | 有可用系统服务则可用，无则明确降级，不要求安装Google语音SDK |
| 原生确认框 | 在APK执行删除/恢复备份/WHOOP断开 | WebChromeClient正常显示确认框，确认或取消均能处理 |
| 文件选择返回重建 | 打开导入文件选择器，旋转导致Activity重建后选择合法备份 | 文件文本等待WebView的restoreBackup函数就绪后再投递，正常显示恢复确认框；不应先调用未定义函数 |

## 实现边界与接口

- `Android.requestSpeech(id)` → `window.nativeSpeechResult(id, ok, {text,error,code})`。code包括cancelled/unavailable/busy/error；系统语音服务可能联网，EXTRA_PREFER_OFFLINE只是偏好而非保证。
- 提醒设置在原有 `reminders/trainingTime/mealTime` 基础上增加 `reminderIntervalMinutes`（UI为15–120，默认30；原生兼容旧值至180）、`reminderMaxCount`（1–5，默认3，总次数含首次）、`quietStart/quietEnd`（默认22:30–07:00；相同表示不设静默）。
- `Android.notificationStatus()` 返回人可读状态；`requestExactAlarms()` 与 `openNotificationSettings()` 只打开系统设置，最终由用户决定权限。
- 只配置每日训练检查和饮食检查两个起始时间；目前还不是每个动作独立闹钟。
- 通知“打开记录”会打开训练或饮食对应页；复提醒与稍后提醒共享当天次数上限。
- 旧备份的检查时间若落在静默窗口，保留健康记录，只暂停发生冲突的那一类提醒，状态中提示调整；不将冲突混入通知权限标记。
- 系统语音识别过程中旋转屏幕或由系统重建页面，WebView页面中的待处理回调可能丢失；需要重新点击语音输入，不应据此自动创建饮食记录。
